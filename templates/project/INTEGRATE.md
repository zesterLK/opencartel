# Integrate Project title

Replace this template with a guide specific to the implementation before marking the project ready. Keep this file at the project root and include it in every source ZIP. Offer the same content as a direct Markdown download from the project's Help or source interface.

## Run the original

State the runtime version and exact independent install, dev, check, test, build and preview commands. Explain the expected local URL, required assets, optional environment variables and asset-base handling. Verify these commands from the extracted ZIP outside the repository. Explain how to verify the archive's source manifest if the project supports it.

## Choose the scope

Explain how to reuse the entire experience, embed it, or extract a named effect. Be explicit about existing component APIs versus refactoring that the integrator must perform. Identify lifecycle cleanup and CSS/DOM isolation needs for the actual runtime.

## Implementation map

List the real entry points, renderer, interaction/state/physics logic, styles, required assets and their notices. Identify dependencies that must travel with an extraction. Document the code, metrics and behaviour that establish fidelity, plus safe customization points and real limitations.

## Verify the integration

List observable baseline states, important interactions, keyboard and touch behaviour, reduced-motion handling, responsive checks, loading/failure states, route reloads and the project's executable checks. Require comparison with an unchanged original and disclosure of intentional differences.

## Copy to your agent

Provide a ready-to-copy brief naming the actual files and behaviours to preserve. Include fields for destination, scope and deliberate changes. Ask the agent to inspect/run the original, preserve unrelated work and license notices, adapt the smallest necessary boundary, and report actual verification. Do not imply that giving an agent this guide alone supplies the source.
